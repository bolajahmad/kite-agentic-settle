# Demo 6: Multi-Provider Agent

This demo shows a single agent managing separate payment channels with multiple providers simultaneously — the pattern for building agentic workflows that consume many paid data sources.

**Source:** `mcp-sdk/examples/06-multi-provider-agent.ts`

## What It Does

1. Opens separate channels with 3 different provider endpoints
2. Fans out requests to all three in parallel
3. Aggregates the results
4. Settles all channels independently

## Running It

```bash
cd mcp-sdk
npm run demo 6
```

## Code Pattern

```typescript
const client = await KiteSettleClient.create({ credential, agentId: "1" });

// Open channels with multiple providers
const channels = await Promise.all([
  client.openChannel({ provider: PROVIDER_A, deposit: parseUnits("2.0", 18), ... }),
  client.openChannel({ provider: PROVIDER_B, deposit: parseUnits("2.0", 18), ... }),
  client.openChannel({ provider: PROVIDER_C, deposit: parseUnits("2.0", 18), ... }),
]);

// Fan out — all calls in parallel
const [reportData, marketData, intelData] = await Promise.all([
  client.callOnChannel(channels[0].channelId, PROVIDER_A_URL).then(r => r.json()),
  client.callOnChannel(channels[1].channelId, PROVIDER_B_URL).then(r => r.json()),
  client.callOnChannel(channels[2].channelId, PROVIDER_C_URL).then(r => r.json()),
]);

// Aggregate
const insight = aggregate(reportData, marketData, intelData);
console.log(insight);

// Settle all
await Promise.all(channels.map(ch => client.initiateSettlement(ch.channelId)));
```

## When to Use This Pattern

- Building orchestrator agents that aggregate multiple data sources
- Using different providers for different data categories
- Isolating spend per provider for accounting purposes
- Allowing per-provider session key scoping
