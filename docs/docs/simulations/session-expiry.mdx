# Demo 2: Session-Bound Channel

This demo shows how a session key can be scoped to a specific channel — useful when you want different agents or roles to have separate payment budgets.

**Source:** `mcp-sdk/examples/02-session-bound-channel.ts`

## What It Does

1. Opens a channel with terms
2. Creates a session key that is bound to that specific channel
3. Makes calls through the channel using the bound session key
4. Demonstrates that the session cannot be used outside the channel

## Running It

```bash
cd mcp-sdk
npm run demo 2
```

## When to Use Session-Bound Channels

| Use Case | Pattern |
|---|---|
| Multi-agent system | One session key per agent, each bound to separate channels |
| Role-based access | Read-only agent has capped session budget |
| API key per client | Separate channel per customer, each with own session |

## Key Points

- Session keys can be scoped to specific providers (by putting provider address in the session rule)
- The session budget and channel deposit are independent caps — both enforce separately
- Session binding is optional; most channels use the default agent session key
